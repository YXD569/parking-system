# 智慧停车管理与数据分析系统 (Parking BI System)

这是一个基于 `uni-app` + `Vue3` 开发的跨平台（H5 / 微信小程序 / App）停车管理系统。

在实现基础的车辆进出场、计费与车位管理之外，我针对**数据分析岗**的需求，在项目中独立开发了一套前端数据分析模块。通过本地数据模拟，实现了从数据采集、清洗、多维指标计算，到可视化看板和报表导出的完整流程。

---

## 一、功能模块说明

### 1. 基础业务功能
*   **入场登记**：录入车牌（支持一键模拟识别），按车辆类型分配车位，处理重复入场和车位满员的异常情况。
*   **出场计费**：根据设定的分时段规则（白天/夜间费率及封顶金额）自动计算停车费，支持模拟支付流程。
*   **车位监控**：利用网格图直观展示所有车位的占用和空闲状态，实时统计使用率。
*   **车辆与规则管理**：支持车辆档案的增删改查（区分临时车/月租车），并可动态调整计费规则。

### 2. 数据分析与可视化
*   **核心数据看板**：使用图表展示“近 7 天营收趋势”和“24 小时车流分布”。
*   **业务指标计算**：自动计算并展示关键指标，包括**车位周转率**、**平均客单价 **、**平均停车时长 **。
*   **对比分析**：计算今日与昨日的营收差异，直观展示环比增幅或降幅。
*   **用户价值分层 **：对已支付订单按车牌聚合，提取最近消费时间、消费频次和总金额，将客户划分为“重要价值客户”、“高频低价值客户”等类别。
*   **业务预警提示**：根据当前数据状态自动生成预警，如车位过载（使用率 > 85%）、营收异常下跌、或存在长期未出场的僵尸车等。
*   **组合查询与数据导出**：支持按车牌、状态、时间范围组合查询。采用纯前端拼接生成 CSV 格式文件，支持一键下载。
*   **异常数据清洗**：可一键识别并清理停留时间过长（超过 7 天）的异常测试数据。

## 二、技术栈

*   **前端框架**：uni-app (Vue3 + Options API)
*   **数据可视化**：uCharts (兼容多端的图表插件)
*   **数据存储**：`uni.setStorageSync` (利用本地缓存模拟数据库及数据流水线)
*   **开发工具**：HBuilderX

## 四、核心逻辑与算法说明

### 1. 计费逻辑
采用分时段计费与封顶策略。扣除免费时长后，以 30 分钟为步长切片，判断该切片落在白天（8:00-20:00）还是夜间时段，按对应费率累加，最后校验总金额是否触发 24 小时封顶限制。

### 2. RFM 分层规则
对已支付的订单数据进行聚合：
*   **R (Recency)**：取该车牌最近一次出场时间。
*   **F (Frequency)**：统计该车牌的累计出场频次。
*   **M (Monetary)**：累加该车牌的消费总额。
*   *当前分类阈值*：金额 ≥ 20 且频次 ≥ 2 划分为【重要价值客户】；频次 ≥ 3 但金额 < 20 划分为【高频低价值客户】。

### 3. 前端数据清洗与导出
*   **数据清洗**：在渲染报表前，遍历在场车辆，若 `当前时间 - 入场时间 > 7天`，则判定为脏数据，前端标记出场并拦截异常计费，避免影响指标计算。
*   **CSV 导出**：手工拼接 CSV 格式字符串，使用 `new Blob(['\uFEFF' + csvContent])` 增加 BOM 头，确保下载后用 Excel 打开时中文不乱码，再通过动态创建 `<a>` 标签触发下载动作。
